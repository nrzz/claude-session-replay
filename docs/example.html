Found it. The two checks disagree about what "logged in" means:

  • /login sends you to / whenever a sid cookie exists.
  • requireAuth treats the same cookie as no session once expiresAt has passed, and sends you back to /login.

An expired cookie is never cleared, so the two routes redirect to each other forever. I'll make readSession the single place that decides, and have /login clear a stale cookie.

ts
export function readSession(req: Request) {
  const id = req.cookies?.[COOKIE];
  if (!id) return null;
  const session = sessions.get(id);
  if (!session || session.expiresAt <= Date.now()) return null; // expired counts as none
  return session;
}

  });
